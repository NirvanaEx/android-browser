# Переработка Upgrid Browser

Дата первичного аудита: 2026-09-07. Проверенная локальная версия: `677eba3`.
Статус: Upgrid Next на Fenix 155.0.1; переработаны плеер, главный экран, меню и планшетная компоновка. Результаты проверок и ограничения — в `tools/fenix/VALIDATION.md`.

## Реализовано 2026-09-07

- Ветка `codex/browser-rebuild`. Текущий `app/` сохраняется как отдельно собираемая версия.
- Чистая основа Firefox Android собрана из тега `FIREFOX_155_0_1_RELEASE`, commit `fb95137a04eb8fe1196cb12f26b100c1e060295c`. Нативный Gecko используется из артефактов той же стабильной версии. Исходники находятся вне репозитория в WSL; pin и команды находятся в `tools/fenix/`.
- Собран отдельный APK `build/fenix/upgrid-next-arm64-debug.apk`: пакет `com.upgrid.browser.next.debug`, название Upgrid Next, Android 8+, только ARM64. Данные старого приложения автоматически не переносятся.
- Плеер открывается внутри текущего движка без обязательного `requestFullscreen()`. Исходный video и его MediaSource остаются в DOM, playback/session не заменяются. Сначала выбирается запущенный ролик между всеми фреймами, затем разворачиваются его контейнеры и родительские iframe. Выход восстанавливает стили страницы. Кнопка встроена в верхнюю адресную панель.
- Убраны Firefox onboarding, рекламные карточки и лишние действия. Главная страница содержит поиск и приватный режим, меню — навигацию, библиотеку, AdBlock, дополнения и настройки. На экранах от 600dp включается штатная верхняя полоса вкладок Fenix. Телеметрия и эксперименты отключены до инициализации Glean.
- Добавлен bootstrap uBlock Origin 1.74.0 с AMO через Fenix AddonManager. Он запускается после регистрации штатного делегата расширений. Автоматические разрешения ограничены `uBlock0@raymondhill.net`; обычные расширения сохраняют стандартные запросы разрешений. Уже установленный и отключённый пользователем uBO не включается заново при каждом старте. Обновления регистрирует штатный менеджер Fenix.
- История, закладки, пароли, вкладки, загрузки и интерфейс дополнений предоставляются исходной реализацией Fenix. Их поведение в этом APK ещё не проверено на устройстве.
- Исправлено наложение панелей управления сайта: скрытие применяется ко всей соседней ветви DOM, отслеживаются новые панели и изменения стилей. При выходе наблюдение отключается, оформление восстанавливается.
- Автоматические проверки: 18 тестов протокола плеера на Node.js, 2 регрессионных теста в Firefox и 5 тестов генератора overlay. Для границы разрешений добавлены Kotlin-тесты и запуск существующих тестов WebExtensionSupport через `tools/fenix/test.sh`.
- Текущий `app/` также успешно собран с исправленным плеером. CI дополнен тестами JavaScript и инструмента переноса; сборка Fenix пока локальная.

Остаётся: проверить конкретные сайты и устройства пользователя, собственные XPI, перенос данных и повседневные сценарии истории/паролей/загрузок. Ускорение браузера без замеров не заявляется. Сводка результатов находится в `tools/fenix/VALIDATION.md`.

## Требования пользователя

- Сохранить отдельный плеер внутри браузера, устранить ненадёжный захват. Пользователь уточнил: плавающее окно поверх других приложений не является целью этой переработки.
- Полноценное повседневное поведение браузера: вкладки, история, сохранение паролей и сопутствующие функции.
- Установка дополнительных расширений, включая собственные.
- Использовать существующие открытые реализации и измерять производительность.
- Сохранить концепцию собственного браузера с uBlock Origin.

Новые требования разрешают пользовательские расширения: прежнее ограничение AGENTS.md на невидимую систему расширений больше не описывает весь продукт. Автоматическое предоставление разрешений остаётся ограниченным встроенным доверенным uBO; пользовательские дополнения требуют отдельного интерфейса разрешений.

Уточнения пользователя: нужен плеер внутри браузера; семейство расширений предложить самостоятельно. Рекомендация — Firefox WebExtensions, включая собственные расширения в этом формате. Совместимость расширений Chrome и Firefox не считать автоматической. PiP уже существует и требует регрессионной проверки при изменениях, но расширение его возможностей не входит в текущий приоритет.

## Открытая основа

Рекомендуемый основной кандидат — Firefox for Android (Fenix), GeckoView и Mozilla Android Components, с Firefox WebExtensions. Для требования «как полноценный браузер» сначала оценить перенос собственного интерфейса и плеера на Fenix: это даёт больше готового поведения, чем самостоятельное подключение каждой функции. Цена — более сложная сборка и сопровождение изменений при обновлениях upstream.

Альтернатива — сохранить небольшой проект и подключить недостающие Android Components по примерам Reference Browser. Она удобнее для собственного интерфейса, но требует больше интеграционных работ. Текущий проект уже использует эти библиотеки; само по себе повторное добавление зависимостей проблемы не решит.

| Источник | Роль | Ограничение |
| --- | --- | --- |
| [Mozilla Firefox / Android](https://github.com/mozilla-firefox/firefox/tree/main/mobile/android) | Основной кандидат; готовое приложение и компоненты | Выбрать стабильную ревизию и проверить самостоятельную сборку до переноса UI |
| [Reference Browser](https://github.com/mozilla-mobile/reference-browser) | Пример подключения библиотек | Сам проект определён как Technology Preview, не готовый конечный продукт |
| [Iceraven](https://github.com/fork-maintainers/iceraven-browser) | Кандидат для изучения изменений Firefox и расширений | Не принимать за основу без отдельной проверки обновлений и сборки |
| [Kiwi](https://github.com/kiwibrowser/src.next) | Пример Chromium-браузера с расширениями | README сообщает о прекращении поддержки после января 2025; исключить как основную базу |
| [AndroidX Media3](https://developer.android.com/media/media3/exoplayer/supported-formats) | Возможный дополнительный плеер для доступных медиапотоков | Не решает обнаружение источника и перенос авторизованной веб-сессии |

Не копировать архивированные старые репозитории Fenix/firefox-android как актуальную базу: разработка перенесена в общий репозиторий Mozilla. Полный upstream и его лицензионные уведомления сохранены во внешнем checkout; собственные изменения воспроизводимо применяются поверх фиксированного commit.

## Состав новой версии

1. Вкладки: обычные и приватные, восстановление после завершения процесса, возврат закрытой вкладки, корректная обработка внешних ссылок и новых окон сайтов.
2. История и закладки: хранилище Places через `browser-storage-sync`, поиск и удаление; исключение приватного просмотра.
3. Пароли: существующее хранилище Mozilla и интеграция Gecko login/autofill с интерфейсом сохранения и обновления; проверить защиту ключей и локальную работу без аккаунта. Отдельно проверить системный менеджер автозаполнения. Синхронизация Google не входит автоматически в «поведение как Chrome».
4. Повседневные функции: загрузки, загрузка файлов на сайты, диалоги страниц, разрешения камеры/микрофона/геолокации, открытие внешних приложений, обработка ошибок и очистка данных.
5. Расширения: установка, включение/отключение, удаление, обновления, параметры и запросы разрешений. Собственные подписанные XPI и разработческий режим для неподписанных дополнений оценивать отдельно на выбранной версии движка.
6. Видео: отдельный контроллер состояния, привязка к вкладке/фрейму/запросу, подтверждение успеха, восстановление страницы после выхода и корректный PiP.

## Видео: способ реализации

Основной путь — оставить декодирование в Gecko и построить надёжный плеер внутри браузера с собственным управлением. Это сохраняет состояние страницы и её авторизацию. Существующий системный Android PiP проверяется на регрессии отдельно.

Нужны обнаружение и ранжирование кандидатов, защита от устаревших сообщений, обработка навигации/замены video/отключения порта, таймауты и понятные ошибки. При проектировании выбора между фреймами отдельно проверить сохранение пользовательского жеста, необходимого для fullscreen/play.

Media3 можно добавить для источников, которые действительно доступны отдельному плееру. `blob:`/MediaSource и защищённые потоки нельзя считать обычными переносимыми URL; поддержка формата в Media3 не гарантирует извлечение и воспроизведение любого ролика сайта.

## Последовательность и критерии готовности

1. Проверить рекомендованную основу Fenix с Firefox WebExtensions и плеером внутри браузера. Собрать чистую выбранную основу, зафиксировать ревизию, воспроизводимую команду сборки и список необходимых отличий.
2. Проверить базовый браузер до переноса оформления: сессии, приватность, формы, загрузки, пароли и разрешения. Проверять миграцию текущих пользовательских данных отдельно.
3. Перенести uBO, минималистичный интерфейс и переработанный плеер отдельными изменениями с проверкой каждой сборки.
4. Подключить пользовательские расширения с их UI и правилами разрешений.
5. Сравнить производительность до и после на одном телефоне: холодный старт, переключение 1/10/30 вкладок, память, плавность, батарея во время видео. Зафиксировать условия и результаты; не обещать ускорение без измерений.

Матрица видео: обычное video; несколько роликов; cross-origin iframe; отложенная загрузка; открытый shadow root; SPA-замена video; повторный захват; отказ fullscreen; поворот; PiP и возврат; смена вкладки; внешняя ссылка во время PiP. Для недоступного источника ожидается понятный отказ без сломанной страницы.

Проверки данных: восстановление обычных вкладок после убийства процесса; отсутствие приватной истории/паролей в сохранении; сохранение и обновление тестового пароля; удаление истории/закладки; загрузка и отправка файла; отмена разрешения расширению.
