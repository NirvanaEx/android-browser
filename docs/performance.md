# Upgrid: производительность, 2026-09-09

Пользователь описывает белые участки при скроллинге страниц с видео и обложками:
через несколько секунд содержимое появляется. Конкретный сайт не требуется раскрывать.
Это согласуется с отставанием отрисовки (checkerboarding), но без записи профиля
не отделяет его от отложенного создания контента самим сайтом.

## Подтверждено

- Распространённый 0.4.1-startup собран через `fenix:assembleDebug`:
  `minifyEnabled = false`, `shrinkResources = false`, Android debugging, debug-channel
  StrictMode и Compose tooling. Native Gecko получен из готового артефакта Mozilla;
  переход на release оптимизирует Android-часть и не означает пересборку/ускорение Gecko.
- Отчёты Xiaomi 2209116AG содержат завершения основного процесса с Android
  `REASON_LOW_MEMORY = 3`, в том числе в фоне (`importance = 400`). Это подтверждает
  давление на память устройства в те моменты, но не измеряет память во время скроллинга
  и не доказывает утечку в браузере. Записи `REASON_OTHER = 13` не считать нехваткой памяти.
- `player.js` вводится при запросе захвата. Наблюдение за DOM и периодические обновления
  состояния относятся к активному плееру; непрерывного поиска видео при обычном скроллинге нет.
- Fenix `Core.kt` явно задаёт `trimMemoryAutomatically = false` со ссылками на upstream
  ошибки восстановления; управление памятью оставлено Gecko/Android. Включать этот
  переключатель без проверки сохранения форм, вкладок и медиа нельзя.

## Первый этап

Добавлена команда `bash tools/fenix/build.sh optimized`: настоящий release-вариант,
штатные оптимизации R8/ресурсов и release-зависимости, без debug-инструментов.
Пакет и локальная подпись должны совпадать с установленным Upgrid; отдельная
проверка итогового APK обязательна. VPS-диагностика сохраняется.
Версия кандидата — 0.4.2-performance (4). Это не утверждение об исправлении скроллинга.

Сборка кандидата успешна: `performance-build-6g.log`, 6m 35s, 4411 задач,
307 выполнено. Первый запуск с 4 GB heap остановлен после подтверждения непрерывного
full GC; повторный запуск использовал 6 GB и одного Gradle worker. APK находится в
`build/fenix/upgrid-next-0.4.2-performance-arm64-release.apk` (125 355 056 байт),
против 166 952 537 байт у 0.4.1: на 24,9% меньше. Это размер файла, не замер RAM/скорости.
SHA-256: `5e2ab9c94024b4f34df24afe09937cf635616459ebc6f006429f5d2b90346b0b`.
Mapping сохранён рядом в `upgrid-next-0.4.2-performance-mapping.zip`.

Проверены подписи обоих APK (совпадают), пакет, версия 4, ARM64, отсутствие
debuggable/sharedUserId, брендинг и profileable в собранном manifest. Наличие
настроенной диагностики проверено внутри DEX без вывода её приватных значений.
`libxul.so` идентичен прежнему APK. Python overlay 5/5, проверка 49 сгенерированных
файлов, `bash -n`, `git diff --check` прошли.

После запроса пользователя на отправку 09.09.2026 проведены проверки на эмуляторе:
обновление с сохранением сессии, три холодных запуска с меню и сохранённой вкладкой,
воспроизведение/выход из плеера, нативный сбой без сети и подтверждённая доставка
после восстановления подключения. Подробности — `tools/fenix/VALIDATION.md`.
APK добавлен в каталог бота под прежним `app_id=upgrid`, запись 22, Test / Build 4.
В каталоге 9 версий, прежние версии и настройки доступа сохранены. Файл доступен
контейнеру Bot API; карточка и кнопка скачивания проверены без личной рассылки.
Пост в канал не создавался. Фактическая выдача файла пользователю не инициировалась.

Анонимный сценарий: `tools/tests/fixtures/media-scroll.html`, три режима (текст,
48 локальных JPEG-обложек, обложки и один ролик). Обложки готовы до начала прокрутки.
Работа всех трёх режимов, 48 карточек и воспроизведение проверены в desktop Firefox.
Страница намеренно создаёт нагрузку на память и не заменяет профиль Android/Gecko.

## Следующие замеры и решения

1. Сравнить debug/release на одном физическом устройстве: холодный запуск,
   открытие меню, смену вкладки. Отдельно записать плавность прокрутки медиастраницы.
2. Повторить с 1/10/30 вкладками и одинаковой температурой устройства. Измерять
   память всех процессов пакета, включая процессы контента, а не только Java heap.
3. Если доминируют фоновые вкладки — рассмотреть выгрузку давно неиспользуемых
   с сохранением сессии и защитой выбранной вкладки, форм, воспроизведения и загрузок.
4. Если задержка сохраняется с одной вкладкой — исследовать профиль Gecko:
   декодирование изображений, JavaScript/layout/paint, compositor и видеодекодер.
   Отложенную сетевую загрузку обложек измерять отдельно.
5. Менять размер области предварительной отрисовки, кэши или число процессов
   только по результатам этих замеров. Увеличение кэшей может усугубить нехватку памяти.

Телефон не подключён к ADB в этой сессии. Ускорение в процентах, устранение белых
участков и улучшение расхода батареи не измерены. Эмулятор с ARM64-трансляцией
пригоден для функциональных проверок, но не для таких выводов о скорости телефона.
