# Плеер 0.6.0

Двойное нажатие по левой половине перематывает на 5 секунд назад, по правой —
вперёд. Одиночное нажатие показывает/скрывает управление. Постоянные кнопки
перемотки убраны; остаются полоса времени и короткий индикатор жеста.
Свайп, удержание и касания самой полосы времени не добавляют лишний шаг.

При сворачивании приложения и смене вкладки видео ставится на паузу.
Возвращение не запускает воспроизведение. Контент-скрипт блокирует повторный
автозапуск приостановленного видео до реального действия пользователя;
нативная кнопка Play разрешает запуск только управляемому элементу.

## Последовательность открытия

1. Выбрать играющее видимое видео среди доступных фреймов и открытых shadow roots.
2. Получить HTTP(S)-источники именно этого видео: `currentSrc`, альтернативы
   `<source>`, публичные API Video.js/JW Player, доступные экземпляры Hls.js,
   dash.js и Shaka. Экземпляр должен быть связан с выбранным video; наличие
   глобального объекта само по себе недостаточно.
3. Для Facebook использовать прогрессивные MP4 с тем же `videoFBID` и длительностью.
   Принимаются HTTPS fbcdn.net, до четырёх вариантов HD/SD/progressive.
4. Открыть отдельное окно Media3. При ошибке попробовать оставшиеся проверенные
   варианты того же видео (не более четырёх, первый кадр — до 15 секунд на вариант).
   HLS/DASH получают MIME, если API сообщает его даже для URL без расширения.
5. Если поток не переносится или варианты не воспроизводятся, открыть **сам
   элемент video** через Fullscreen API Gecko и показать управление Upgrid.
   MSE, авторизация и лицензированное декодирование остаются у движка сайта.
   Ни видео, ни его родители не перемещаются. Геометрию задаёт Fullscreen API;
   только object-fit/object-position самого видео временно исправляются на
   contain/центр, если сайт обрезал кадр. При выходе эти свойства восстанавливаются.
6. Если Gecko требует свежего жеста, показать временную кнопку «Открыть плеер»
   над выбранным видео. Настоящее нажатие разрешает fullscreen; синтетический
   click не принимается. Кнопка удаляется при запуске, отмене, смене вкладки
   или истечении 30 секунд. При запрете fullscreen остаётся просмотр на странице.

Это расширяет совместимость, но не гарантирует все сайты. Закрытый shadow root,
запрет fullscreen в iframe/Permissions Policy, отсутствие рабочего декодера,
изменения API сайта или потеря доступа к ролику могут помешать открытию.
Прямое извлечение подписей YouTube и разделённых дорожек не реализовано;
для такого видео предусмотрен путь через Gecko. Отдельный перенос DRM-лицензий,
cookies и токенов не выполняется.

## Владение воспроизведением

Media3 приостанавливает исходное видео и удерживает его на паузе. При возврате
передаёт позицию только тому же источнику, для Facebook сверяет Video ID,
для адаптеров MSE — исходный URL публичного API. Отмена/навигация не должна
перематывать соседний ролик, даже когда сайт повторно использует тот же элемент.
При закрытии освобождаются декодер, буферы, audio focus и окно. Новый
GeckoRuntime не создаётся; используется существующий `Components.core` Fenix.

Старый CSS-режим остаётся только у отдельно собираемого legacy `app/`.
Fenix его не использует. Дефект 0.4.2 возникал именно из-за CSS родительских
блоков, desktop viewport и iframe: управление заполняло экран, а видео обрезалось.

Адреса живут только в памяти. Диагностика содержит технические коды без URL,
заголовков и текстов сетевых исключений. Referer ограничен origin страницы
и отключается при no-referrer или HTTPS→HTTP. История, пароли, uBO и разрешения
пользовательских расширений сохраняют архитектуру браузера.

Адаптер Facebook не читает токены и не вызывает API Facebook: сопоставляет
уже загруженный JSON. Лимиты: 4 МиБ, 20 000 узлов, 1,5 секунды, с уступкой
управления между порциями разбора. Live/DRM не извлекаются в MP4; доступен
резервный путь через движок, если сам сайт разрешает fullscreen видео.

## Проверки и источники API

`node --test tools/tests/player.test.cjs` проверяет протокол/выбор источника
на модели DOM. `player-browser.test.cjs` проверяет реальное поведение Firefox,
blob/MSE, размеры fullscreen, сохранность DOM, активацию и ручной запуск.
На Android необходимы первый кадр, жесты (`player-tap-seek.ps1`), сворачивание,
вкладки, возврат, поворот, ошибочный источник, `DiagnosticsProbe/browser_empty`
и холодные запуски с сохранённой вкладкой/меню. Результаты: `tools/fenix/VALIDATION.md`.

Документация: [Media3](https://developer.android.com/media/media3/exoplayer/supported-formats),
[Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen),
[Hls.js](https://hlsjs.video-dev.org/api-docs/hls.js.hls),
[dash.js](https://cdn.dashjs.org/latest/jsdoc/module-MediaPlayer.html),
[Video.js](https://docs.videojs.com/player),
[Shaka](https://shaka-project.github.io/shaka-player/docs/api/shaka.Player.html).
