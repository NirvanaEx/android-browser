# Upgrid Chromium — разработка из исходников

Ветка выбрана пользователем 28.09.2026. Это отдельная реализация на исходниках
Chromium, не перепаковка Banana APK и не WebView-оболочка.

База для сопоставления с Banana закреплена в `upstream.json`: Chromium
146.0.7680.31 / `4d3225104176d18430bb7bef9f67394686316c2f`.
Этот старый тег — исследовательская база, не одобренный релиз для распространения.
Исходный APK нужен только как эталон; библиотека Banana не включается в сборку.

## Подготовка

В Linux/WSL, из корня этой рабочей папки:

```sh
python3 tools/chromium/preflight.py --report build/chromium/preflight.json
python3 tools/chromium/prepare.py --sync --hooks
python3 tools/chromium/build.py
```

Подготовка закрепляет Chromium и depot_tools по commit, скачивает зависимости
Android с одним worker и не меняет глобальный профиль WSL. Повторный запуск
не сбрасывает локальные изменения. По умолчанию файлы размещаются отдельно:
`~/.cache/upgrid/chromium/src` и `~/.cache/upgrid/chromium/depot_tools`.

Системные зависимости Chromium устанавливаются штатным
`build/install-build-deps.sh` внутри его checkout, после проверки состава пакетов.
Этот шаг меняет Linux-окружение и здесь не запускается неявно.

Предварительная проверка сверяет не только виртуальную ёмкость WSL, но и свободное
место на Windows-диске с VHD. При недостаточных ресурсах большой checkout не
запускается. Согласованный профиль 6 ГБ RAM не повышается автоматически.

## Готовность

Проект ещё не является готовым браузером. Реализация нативного управления
прошла компиляцию изменённых C++/Blink-модулей и Java. Полная сборка APK и
проверки воспроизведения на Android ещё не завершены. Полная приёмка и
границы восстановления Banana: `../../docs/chromium-migration.md`.

Полная сборка из исходников обязательна до любых утверждений о работоспособности.
Ни успешное применение overlay, ни тесты протокола не подтверждают видеокадр,
fullscreen, плавность или соответствие Banana.

## Реализация и проверка

`overlay/` содержит собственные изменения Chromium, переносимые через
`apply-overlay.py`. Скрипт проверяет точный commit, все точки вставки и локальные
изменения перед записью; квитанция позволяет безопасно обновить ранее применённый
overlay. Внешний checkout — производная копия, правки нужно делать здесь.

- Mojo связывает команды с элементом, URL, экземпляром декодера и поколением
  загрузки. Повторная загрузка того же URL тоже инвалидирует старое управление.
- Процесс браузера выбирает видео среди активных фреймов, включая OOPIF;
  список фреймов и время ожидания ограничены. Java не получает URL или cookies.
- Renderer берёт кандидатов из внутреннего реестра медиаэлементов Chromium,
  включая Shadow DOM; обход остальных DOM-узлов страницы не требуется.
- Плеер сохраняет Chromium fullscreen и существующую медиасессию. Прозрачный
  Android dialog отображает управление после подтверждения fullscreen.
- Обычный выход сохраняет play/pause; скрытие вкладки, фон и уничтожение
  контроллера приостанавливают выбранное видео. Запоздалые ответы проверяют
  поколение операции. Отмена учитывает ещё не завершившийся запрос fullscreen.
- Ручной поворот защищён от запросов сайта в пределах окна плеера; после выхода
  обычный механизм ориентации Chromium снова доступен.
- Горизонтальная перемотка и seek bar показывают выбранную позицию и отправляют
  один seek при отпускании. Временная пауза сохраняет исходный Play/Pause;
  выход в фон отменяет автоматическое возобновление. Проверка на телефоне ожидается.
- Адаптер качества и субтитров YouTube работает только с API плеера, которому
  принадлежит выбранный fullscreen video, и повторно проверяет источник.

Быстрые проверки инструментов:

```sh
python3 -m unittest discover -s tools/chromium/tests -v
node --test tools/chromium/tests/youtube-options.test.cjs
python3 tools/chromium/build.py --generate-only
python3 tools/chromium/build.py --check-integration
```

Python и Node проверяют инструменты и изолированную логику адаптера. Это не
проверка настоящего YouTube. Overlay также добавляет Blink- и Robolectric-тесты
контролов, смены источника и ручной ориентации; их выполнение требует отдельных
тестовых сборок Chromium и не входит в `--check-integration`.

Проверка `ScreenOrientationProviderImplTest` выполнена 28.09.2026: 10/10 прошли
(5 методов на Android SDK 29 и 36 в Robolectric), без повторных попыток.
Это включает изоляцию ручного поворота по окнам и отмену отложенных запросов сайта.
Blink-тесты пока не выполнялись. Жесты и видеокадр на телефоне ещё не проверены.

Для повторения проверки ориентации:

```sh
python3 tools/chromium/build.py --target content_junit_tests
cd ~/.cache/upgrid/chromium/src
../depot_tools/vpython3 out/Upgrid/bin/run_content_junit_tests \
  --test-filter '*ScreenOrientationProviderImplTest*' --shards 1 --num-retries 0
```

Сборка использует `-j 1`, отказывается менять чужую выходную папку или GN args,
останавливает собственную группу процессов при остатке менее 20 ГиБ на диске
Windows. Для начала после checkout требуется 35 ГиБ свободного места.
`build.py --target <ninja-target>` позволяет проверить отдельную цель.

Android package экспериментальной сборки — `com.upgrid.chromium`.
Текущий профиль — debug; окончательные замеры плавности требуют оптимизированной
сборки. Не сравнивать скорость debug-Upgrid с релизным Banana как итоговый результат.
APK ожидается в `~/.cache/upgrid/chromium/src/out/Upgrid/apks/ChromePublic.apk`.
Квитанция фиксирует Chromium commit, хеши overlay и GN args, цели и SHA-256 APK.
Она **не** разрешает публикацию: требуются проверки приёмки.

Для вызова из PowerShell использовать `wsl.exe -d Ubuntu --cd / --exec …`;
на этой машине запуск с наследованием рабочего каталога периодически даёт
`Wsl/Service/0x8007274c`. Это отдельно от ошибок компиляции.
