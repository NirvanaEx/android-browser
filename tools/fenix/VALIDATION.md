## Падение из отчёта устройства — 2026-09-08, 0.4.1-startup

Диагностика впервые подтвердила причину на устройстве пользователя: Xiaomi 2209116AG, API 33 / Android 13 по данным системы, ARM64. Свежие отчёты 57f41862-b6ce-4090-92c0-1fec43271710 и f26d0d2d-f2d9-4011-b973-84d71fe9d280 содержат одинаковый NullPointerException: BaseBrowserFragment.browserToolbar → collapseBrowserView → UpgridPlayerFeature.show(false) → конструктор плеера → onViewCreated. Такой же стек присутствует среди восстановленных отчётов предыдущей версии 1.0.2637.

При асинхронном восстановлении BrowserFragment может уже существовать, а выбранная вкладка — ещё отсутствовать. initializeUI(view) намеренно пропускает создание toolbar. Наш прежний код независимо от этого создавал плеер; его начальный show(false) пытался восстановить отсутствующую панель. Проверка только стартового экрана без вкладок не охватывала этот сценарий.

Исправление: создание плеера перенесено в ветку с существующей вкладкой, после инициализации toolbar/engine UI; feature хранится до уничтожения view. Начальное скрытое состояние не вызывает callbacks браузера; повторное скрытие и остановка неактивного плеера не восстанавливают панели. Команда отмены ожидающего захвата при остановке сохранена. Сбор диагностики не изменён. Версия 0.4.1-startup, versionCode 3.

## Изменения

Плеер открывает оригинальный video внутри браузера без HTML fullscreen и без замены MediaSource. Сначала выбирается запущенный ролик между фреймами, затем разворачиваются его контейнеры и родительские iframe. Выход восстанавливает страницу. Ошибки декодера не должны приводить к успешному захвату чёрного экрана.
