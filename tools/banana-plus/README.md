# Общая защита переходов Banana Plus

Установлены нативная защита переходов 1.0.1 (ChromeXt 3.8.3-bananaplus.2) и userscript click-guard.user.js 2.1.3. Защита действует глобально на HTTP/HTTPS-сайтах и портах в существующем org.triple.banana на телефоне. Модуль собран в GitHub Actions; готовый APK обновлён с прежней подписью и данными. Предыдущие версии сохранены для сравнения.

Нативный модуль останавливает переходы на известные рекламные адреса, включая серверные 301/302/303/307/308 и цепочки редиректов. Он запускается до навигации вкладок и работает без ПК. Обычные разрешённые редиректы сохраняются. Подробности: [NATIVE-GUARD.md](NATIVE-GUARD.md).

## Проверка установленного нативного модуля 1.0.1

[Итоговая квитанция](verification-native-2026-10-16.json): 19 серверных/стартовых сценариев, в том числе 301/302/303/307/308, цепочки, новые вкладки, три холодных запуска и работа с отключённым соединением отладки. Исходный документ сохраняется, ответы рекламных адресов в заблокированных проверках отсутствуют. Разрешённые редиректы проходят.

Дополнительно прошли 23 контрольных сценария кликов, пять проверок Play и 16 отложенных атак до 120 секунд. На pervtube.net и pxp.farm повторены минута ожидания, первый переход, первый Play, две минуты воспроизведения и три повторных касания. Рекламных вкладок и подмены основной страницы в этих проверках нет. SHA-256 установленного APK совпал с проверенным файлом; новых сбоев основного процесса после окончательной установки нет. Временные подключения удалены.

Повторяемый серверный стенд: [device-tests/README.md](device-tests/README.md).

## Исправленные сценарии

- Программные popup, несколько окон одного нажатия, открытия по таймеру и цепочки «popup, затем подмена текущей вкладки».
- Подмена href во время pointer/touch/click, включая ссылки target=_blank и ссылки с ролью кнопки.
- Поглощение первого нажатия рекламой: после заблокированного перехвата открывается исходная ссылка. Для новой вкладки проверяется отсутствие дубликатов.
- Нестандартные кнопки плеера и реклама, которая поглощает первый Play. Возобновляется только уже связанный с выбранным элементом источник, если видео было на паузе и пользователь нажал Play. Ручная пауза, настройки, фон и замена источника не вызывают автозапуск.
- Пустые прозрачные ссылки поверх видео; всплывающие окна из same-origin, cross-origin и about:blank iframe.
- Автоматическая замена основной страницы без явного действия пользователя, в том числе внутри того же сайта. Браузерные Back/Forward/Reload и маршрутизация SPA сохраняются.

Сторонние iframe получают sandbox без разрешения popup и навигации основной вкладки. Скрипты, формы, исходный origin и presentation разрешены; атрибут allowfullscreen не меняется. Реальное воспроизведение проверено. Виджеты, которые намеренно требуют ухода из iframe в основную вкладку или отдельного окна, могут потребовать отдельного открытия.

Для заблокированного нужного перехода остаётся одноразовая кнопка «Открыть». Адрес показывается без пути и параметров. Автоматические переходы иногда могут быть легитимными; они тоже требуют этой кнопки.

## Установка и обслуживание

Импортировать файл через существующий менеджер ChromeXt, включить «Banana Plus — защита переходов» и перезагрузить открытые страницы. Namespace/name сохранены с 1.0.2: обновляется один скрипт, остальные не изменяются.

Document-start нужен для раннего запуска. Регулярное include компенсирует сопоставление ChromeXt, при котором http://*/* пропускает двоеточие порта. Grant frames включает механизм ChromeXt для фреймов; доступные same-origin копии open() и sandbox обрабатываются дополнительно.

window.__bananaClickGuard возвращает только версию, область действия, счётчики и домен последнего заблокированного перехода. История переходов, cookies, пароли, параметры URL и содержимое форм не записываются.

## Подтверждённые границы

Ограничение старого userscript на серверные редиректы закрыто нативным модулем 1.0.1 для известных рекламных адресов. Userscript по-прежнему отвечает за клики, popup и плеер; он зависит от своевременного запуска ChromeXt и не является границей безопасности против произвольного кода страницы. Нативный фильтр использует списки доменов и не гарантирует распознавание новых неизвестных рекламных адресов.

Реклама, вшитая в сам видеопоток, и обычные рекламные элементы внутри страницы не определяются этой защитой навигации. Сетевые и косметические правила браузера работают отдельно. Отсутствие стандартных DOM-признаков рекламы в плеере не доказывает отсутствие рекламных кадров в потоке.

VPN отложен пользователем. Настройки сети телефона и сервера не менялись; временный таймаут экрана и подключения отладки после проверок восстановлены/удалены.

## Историческая проверка прототипа до обновления модуля, 2026-10-16

На том же телефоне отдельно проверен перехват Document-ответов через CDP Fetch до перехода по Location. Контрольный 302 без перехвата достиг адреса /ad; с перехватом 301/302/303/307/308 и цепочка 302 остановлены без запроса к /ad, исходный документ сохранился. Относительный и междоменный разрешённые 302 прошли. Все 9 проверок завершились успешно. [Квитанция](verification-server-redirect-2026-10-16.json).

Это диагностический прототип с заранее заданным контрольным адресом, а не распознавание рекламы и не установленная постоянная функция. Перехват отключён, тестовая вкладка закрыта, forward/reverse удалены. APK и userscript 2.1.3 не менялись.

Проверены доступные API встроенного ChromeXt: общий websocket-мост разрешён только странице DevTools; GM-HTTP обрабатывает собственные запросы и не перехватывает навигацию Chromium. Постоянный сетевой фильтр не предоставлен текущему userscript. Для внедрения необходима нативная интеграция во встроенный модуль с правилами рекламных адресов, запуском до навигации и проверками новых вкладок/холодного старта. Этот раздел описывает состояние до выпуска нативного модуля; актуальные результаты приведены в отдельной квитанции нативной защиты.
